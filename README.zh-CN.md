# reader-ready · 为读者而写

[English](README.md) · 简体中文

让内容、口吻和信息详略贴合实际读者，保留作者原意、证据和文体要求。

同一套编辑判断贯穿起草、修改和交付检查，适用于申请材料、报告、文章、表格、PPT、讲稿、科研论文，以及含文字的图表。

## 工作方式

**明确读者与用途 → 判断信息取舍 → 组织表达 → 检查成品。**

1. **明确使用场景。** 判断读者是谁、材料用来做什么、由谁讲述、采用什么文体，以及文件中的哪些内容会一同交付。
2. **判断信息取舍。** 保留帮助读者理解、评价、查找或行动的信息；有用但口吻或位置不当的内容予以改写；制作备注移到工作对话或已有的合适记录；没有信息增量的内容直接删除。
3. **组织表达。** 采用合适的作者口吻，突出信息主次，保持文体所需的正式程度，清理妨碍理解的多余解释和模板化表达。
4. **检查实际成品。** 借助相应格式的工具，检查读者会收到的文字，包括相关讲稿、图注和已经嵌入图片的文字。

这些判断依赖具体语境。无关的项目名称可以直接省略，无需补一个替代名称。路径在复现交接中可能必不可少，在共享演示文稿中则可能毫无帮助。已经清楚的文字可以原样保留。

## 同一思路如何用于不同材料

| 场景 | 共同逻辑的具体应用 |
| --- | --- |
| 申请与个人材料 | 采用合适的作者口吻，写清有依据的身份和贡献；保留规定字段，省略重复明显信息的标签。 |
| 证明与支撑材料 | 保留证据和有用说明，把截图拼接过程、页面替换提醒留在工作沟通中。 |
| 报告、文章与表单 | 围绕读者的任务安排信息，保留有效引用和必要内容，压缩重复解释与空泛铺垫。 |
| PPT 与讲稿 | 让页面和讲稿服务于表达，移除共享材料中无关的本地路径与制作指令。 |
| 科研图与图表 | 保留理解结果所需的标签、定义和证据，省略没有读者价值的内部名称与流程标签。 |
| 科研论文 | 用正式学术表达推进研究论证，让主张与证据相称，把限定放在有助于理解的位置。 |
| 技术交接与教程 | 路径、版本和待办属于收件人需要的信息时，予以保留。 |

### 应用于科研写作时

科研写作沿用全部共同规则，起草或修改论文时再读取[科研写作参考](references/scientific-writing.zh-CN.md)，细化摘要、引言、方法、结果、讨论和图注的处理。

- **保持学术文体。** 使用准确、稳定的术语和符合学科惯例的句式，按需要采用被动句或第一人称。
- **建立清楚的研究主线。** 连接研究问题、知识缺口、证据、发现与贡献；允许调整结构时，按材料在论证中的作用排序，避免写成分析过程的流水账。
- **直接表达有依据的发现。** 已经写成相关关系的结果，通常无需自动追加否认因果的句子。减少重复道歉和预先辩解，把实质限定放在读者需要的位置。
- **保留证据的完整含义。** 保留统计信息、样本单位、引文、影响解释的不利发现及局限。文章的吸引力来自问题与发现，主张的强度与证据相称。

例如，观察性研究的设计和局限已经交代清楚时，“X 与 Y 相关”可能已足够。每次报告相关性都追加“但本研究不能证明因果关系”，只是重复已经表达的边界。如果上下文暗示了因果，则应修改这一暗示，或保留它确实需要的具体限定。

## 使用

可以直接对助手说：

> 用 reader-ready 整理这份给评审看的申请材料，保留规定字段，以我的口吻写。

> 用 reader-ready 修改论文结果和讨论，保留正式科研表达，突出研究主线，去掉重复的防御性措辞。

> 用 reader-ready 检查这份准备发给合作者的 PPT，包括讲稿和图里的文字。

> 用 reader-ready 审阅这份文件，只给修改建议，不改文件。

按请求的范围执行：需要起草就起草，需要修改就修改，只要求审阅就给建议。在 Codex CLI 或 IDE 扩展中，也可以使用 `$reader-ready`。支持自动选择的宿主可以根据任务匹配使用。

## 安装

通过社区 [Skills CLI](https://github.com/vercel-labs/skills) 安装，按提示选择使用的助手和安装范围：

```sh
npx skills add LianaSakana001/reader-ready --skill reader-ready
```

安装到用户范围，供 Codex 使用：

```sh
npx skills add LianaSakana001/reader-ready --skill reader-ready --agent codex --global
```

也可以把仓库复制到所用助手的技能目录下，文件夹命名为 `reader-ready`，保留 `SKILL.md`、`references/` 和 `agents/` 的相对位置。Codex 支持的目录见[官方技能文档](https://learn.chatgpt.com/docs/build-skills)。使用这些指令不需要安装 Python 包、配置模型 API 密钥或依赖其他写作 skill。

### 指令语言

默认入口 `SKILL.md` 使用英文，`SKILL.zh-CN.md` 是等价中文版。两个版本均可按任务输出中文或英文。

需要中文指令时，在**独立的安装副本中**把 `SKILL.zh-CN.md` 复制为 `SKILL.md`，同时保留 `references/` 和 `agents/`。[Release](https://github.com/LianaSakana001/reader-ready/releases) 提供已经整理好的中英文安装包。安装其中一个即可，名称都为 `reader-ready`，无需重复加载。源仓库中的两个版本保持不变，便于后续更新。

## 项目内容与执行方式

- [SKILL.md](SKILL.md) / [SKILL.zh-CN.md](SKILL.zh-CN.md)：等价的中英文核心指令。
- `references/`：中英文编辑案例和科研写作指导，按任务需要读取。
- `agents/openai.yaml`：界面展示信息。
- [tests/](tests/README.md)：双语行为案例和验证方法。
- [SOURCES.md](SOURCES.md)：参考来源、固定版本和取舍说明。

核心指令负责共同的编辑判断，参考文件补充特定场景的细节；中英文指令采用相同逻辑。

文件读写、图片文字识别和渲染检查由宿主工具完成；reader-ready 负责编辑判断与检查范围，助手根据实际完成的检查说明交付状态。

欢迎补充真实适用的修改案例、应当保留原文的反例，以及双语一致性修正。请勿在公开 issue 中提交私人材料。行为发生变化时同步更新中英文版，并参考[验证案例](tests/README.md)检查。
