# Editorial examples

These teaching examples use only the details needed to explain the decision. Facts required for each edit are supplied in its context. Apply the decision, not the exact wording.

## 1. A private project name on a figure

Context: a seminar plot carries an internal project code. It compares microglial proportions in control and treated samples, without establishing a significant difference.

- Before: an internal project code followed by `final audit · microglia`.
- After: `Microglial proportions in control and treated samples`
- Keep group labels, sample sizes, units, and statistical annotations. Do not turn the title into a claim that treatment increased microglia.
- If axes and an existing caption already explain the comparison, just remove the internal code and audit label; no new title is needed.
- If a code is a published cohort name needed for interpretation, explain it where appropriate and retain it.

## 2. Screenshot assembly

Context: a supporting page contains an authentic revision notice dated 12 June 2026.

- Before: `Revision notice, 12 June 2026. Three screenshots were stitched vertically.`
- After: `Revision notice, 12 June 2026.`
- Preserve original evidence. A methods appendix about image assembly would have a reason to describe the procedure.

## 3. Editing instructions in a submission

- Before: `Evidence pending. Replace this page and update the contents once received.`
- Decision: follow up outside the submission. Obtain the evidence or resolve the incomplete item before claiming readiness. Do not silently delete the note and announce that the package is complete.
- Keep `Submitted; not yet accepted` when it describes the real publication status.

## 4. Personal authorship and contribution

Context: the source author list confirms sixth authorship; the user confirms responsibility for data analysis and visualization.

- Before: `The applicant is a contributing author.`
- After, in an achievement entry: `Sixth author. Contribution: data analysis and visualization.`
- After, in a personal statement: `As sixth author, I contributed data analysis and visualization.`
- Do not infer contribution from author order. Without the source facts, omit unnecessary narration but do not invent a rank.
- Keep `Applicant name` as an official form label. A referee may appropriately write `The applicant contributed…`.

## 5. Redundant identity labels

- Before: a cover already gives the person's name and adds `Named version`.
- After: retain the name and omit the redundant label. No replacement label is needed.
- Keep version distinctions when recipients genuinely need them, such as separately requested blinded and unblinded review copies.

## 6. A shared presentation

Context: editable slides will be sent to colleagues. A local path in the speaker notes identifies the input image.

- Before: a local image path followed by `The treatment group had a lower median score.`
- Notes: `The treatment group had a lower median score.`
- Retain useful bibliographic or public-data attribution. Keep the local asset mapping outside shared notes if needed for further work; do not delete the source image or break its link.
- An internal reproduction handoff may need an actual path. A software tutorial may need a path example.

## 7. Role information and original evidence

Context: a participation summary lists a meeting; the attached badge records a staff role. No speaking or award claim is made.

- A redundant `Badge category: staff` can be omitted from the authored summary when the role is not relevant to its purpose.
- Preserve the badge. If a requested category distinguishes invited speakers from staff, state the actual role; do not omit it in a way that implies a speaking achievement.

## 8. The purpose of a panel

- A biological-results talk should use panels that support its question. An unrelated `All export checks passed` panel adds production detail.
- A batch-correction methods review needs relevant before/after QC and limitations. Preserve that evidence even when it was generated during analysis.
- Keep underlying checks and analysis records intact. Selecting presentation content does not authorize removing analysis files.

## 9. Scientific wording

- Before: `This groundbreaking result proves that X causes Y.`
- Context: the reported analysis supports an association, and the source states that causality remains unresolved.
- After: `X was associated with Y; causality remains unresolved.`
- Preserve effect size, uncertainty, statistical significance when supported, and citations. Never invent these to fill a gap.

## 10. Formulas, evidence references, and editorial labels

- In a report, a column headed `Internal run label` may be irrelevant to the recipient. Check dependencies before excluding it from the shared view; preserve formulas and raw data.
- `See Appendix B` helps a reader locate evidence and should remain. Repetition of that navigation on every page may not help.
- Remove `Checked against your instructions; no internal traces remain` from the report itself. Verification belongs in the working conversation when useful.

## 11. Good prose needs no performance

`Save the file before closing the window. Unsaved changes will be lost.` can remain unchanged. Do not add personality, deliberate errors, or a style score. The same applies to clear formal prose and useful three-item lists.

## 12. Text inside an image

If a slide title is clean but its embedded plot still carries an internal project code and `export check`, changing only the title does not solve the problem. Inspect the plot, use its editable source when available, and verify the regenerated result. If only a raster image is available and cannot be safely edited, tell the user what remains; do not pretend the embedded text has been fixed.
